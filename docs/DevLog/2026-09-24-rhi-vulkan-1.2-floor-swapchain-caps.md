# 2026-09-24 · RHI 卫生批：Vulkan 1.2 下限契约化 + 交换链按 surface 能力选择（审查 F-12 收窄版）

来源：[全栈审查](../Reports/2026-09-24-code-review-546a755.md) F-12 复核后的取舍——
完整实现 1.1 设备的 `VK_EXT_descriptor_indexing`/`VK_EXT_host_query_reset` 版 feature
链**不做**：2026 年仍在维护驱动的桌面 GPU 基本报 1.3，"只报 1.1 且带 dynR/sync2 KHR
扩展"的设备近空集，且引擎 bindless 重度依赖下的上古驱动质量不可信（02 分册口径
本就是"目标 1.3"）。取报告给的另一分支：**明确最低版本并拒绝更低设备**。

**修复（`RHI.cpp` 两处）**：

- **设备枚举 1.2 下限**：`props.apiVersion < VK_API_VERSION_1_2` 的设备在枚举期跳过
  并留可解释日志（"bindless core 特性不可用"）。此前 1.1 设备若带 dynR/sync2 扩展
  会被选中，随后 Debug 断言 abort / Release 带 1.2 core 特性链 `vkCreateDevice`
  验证层报错——"神秘失败"变成显式契约拒绝。1.2 legacy KHR 分支（dynR/sync2 扩展
  启用 + 1.2 core 特性链）维持原样，该路径本就正确。
- **交换链 usage/alpha 按能力交集**：`imageUsage` 的 `TRANSFER_SRC`（调试截屏用）
  仅在 `caps.supportedUsageFlags` 支持时请求，缺能力降级 + 告警日志（原硬请求在
  Wayland/远程桌面/VM 类 surface 会整链创建失败）；`compositeAlpha` 按
  `supportedCompositeAlpha` 回退（OPAQUE → INHERIT → PRE/PRE_MULTIPLIED →
  POST_MULTIPLIED，规范保证至少一位置位）。
- **02 分册登记**：分册头新增"运行时下限"契约注记（1.2 下限 + 不实现 EXT 版链的
  理由 + 交换链能力交集语义），文档与代码对齐。

**验收**（本机 RX 590 / MoltenVK 1.3.357，能力含 TRANSFER_SRC+OPAQUE → flags 与
旧行为逐位一致，属零漂移改动）：

- `rhi-smoke --frames 300 --validate`：validation layer enabled、**零 VUID 报错**、
  exit OK；
- `editor-regression.sh full` **13/13**（首轮 smoke-drag 一次注入时序飘忽——单跑
  三连绿、重跑全绿，与 09 §8 记录的 smoke-ui 同机制类，非本批引入：改动面仅交换链
  创建 flags，本机能力下与旧值相同）。
