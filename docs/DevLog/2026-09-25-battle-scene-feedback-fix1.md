# 2026-09-25 · Battle 场第一轮手测反馈修复——可视性/假 fps/模拟吞吐真相

用户手测三反馈：①同屏单位远少于预期、大量看不到；②F3 Profiler 24fps 而
游戏 HUD 显示 60；③画面明显发卡。三因皆实锤，一并修：

## ① 可视性：布阵太远 + 飞剑型站桩

旧布阵 x 起点 |x|≥1123（71 列 × 26 间距方阵），而默认视野半宽 ~640——开战
前两军全在屏外；飞剑型无 Chase 永不移动 → 一半兵力永久不可见。
**修**：前沿贴中线（kFrontGap=80，两军前沿隔 160px）、间距 26→18、行数定
36（帘幕高 ≈ 视野高）；飞剑型加 Chase（KeepRange 220）前压到射程内停住——
两型都进场，视野装不下的梯队边走边入画；补充兵改从本方后带入列（行军流可见）。

## ② HUD fps 60 是假数：固定步长语义误用

`Time.DeltaTime` = 固定模拟步长（SDK 注释明示"固定步长语义"），1/dt 恒 60，
与渲染帧率无关。**修**：改 `Stopwatch` 墙钟计**模拟吞吐步/s**（步数/墙钟差），
HUD 与存档键改 `rvb.steps`；渲染帧率明确归 F3（README 口径改写）。旧键
`rvb.fps` 是历史残留（Save 无删除 API，不清理，读数以 rvb.steps 为准）。

## ③ 发卡主因 = 模拟吞吐跌穿（不只是渲染）

诚实读数揭示真相：**10000 单位全面接战时模拟吞吐 = 33 步/s（目标 60）**——
逻辑侧先到瓶颈，固定步长追帧在低吞吐下呈现为卡顿。本机标定（2400 帧跑）：

| 规模 | 模拟吞吐 |
|---|---|
| 6000 单位（kPerSide=3000） | **60 步/s 满速** |
| 10000 单位（kPerSide=5000） | **33 步/s** |

非线性主因 = 密度：中央绞肉团越密，Hazard 触发/分离邻居/弹幕 Hitbox 查询
越贵（对照 bench-survivor 83fps 是万怪**追玩家一路纵队**的密度，非万单位
互咬网格）。配套减载：飞剑占比 0.5→0.35、射速 1.5s→2.2s 档（场上活弹
~5000→~2400）。

## 验证

- dotnet 0 error；2400 帧跑零异常、byte-exact 往返；3k/5k 两档标定如上表。
- 3k 档战损正常（40s 双方 ~1400 存活 = 阈值补充节奏在工作）。

## 结论与用法口径

场景本身工作正常——**33 步/s 是这台机器在万单位互咬密度下的真实测量**，
不是缺陷。要流畅观感 kPerSide=3000；要压极限 5000~10000 并用 F3 逐系统 ms
（Hitbox/Separation/Animator/渲染段）定位热点回灌引擎侧优化（候选：Hazard
查询降频、分离密度截断收紧、弹幕 Hitbox 分层）。观感测试时关 SceneView
（双视口双份画战场）。
