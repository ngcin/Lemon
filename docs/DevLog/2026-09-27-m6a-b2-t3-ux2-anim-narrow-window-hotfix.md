# 2026-09-27 M6a 批② T3-UX2 热修：动画面板窄窗自适应（"帧全在下面/右侧空白"根因 = 窗口 ~300px 宽）

## 事件

用户截图反馈 T3-UX2 后"选好帧全部在下面、不在右侧，完全没法编辑"。截图取证
（裁剪放大逐区核对：左列内容完整渲染于 x<310，"帧 1/9"信息出现在带边框框内，
其余为空停靠区）定位根因：**Animation 窗口被拖成 ~300px 窄窗**——固定 230px
左列把右区压成 ~60px，工具条/帧网格溢出裁切即"右侧空白"。布局对窗口宽度零
防御。

修复（v3.2，[批文件 §6](../Plans/M6a/2026-09-27-b2-t3-ux2-anim-workbench-round2.md)）：

- 窄窗自适应：可用宽 ≥480 = 并排（列宽 min(230, 30%)）；更窄 = 上下堆叠（列 =
  顶部 38% 横条）。DrawLeftColumn 参数化 (width/height/sameLineAfter)。
- 右区整体进 `##right` child——超宽出滚动条而非裁切丢失。
- 「保存」提前至「+ 添加帧」旁（窄窗保命键先活）。
- 开集自动选中首个动画（旧版回落空提示行 = "看不见任何东西"的放大器）。

## 教训

- 停靠面板的布局必须按**可用宽度的比例**分配固定列（Godot/Unity 的列都可折叠/
  比例化），固定像素列在用户拖拽出的窄窗下把主编辑区挤没——截图取证时先量
  "内容实际占据的像素范围"再对照代码假设，比从控件缺失倒推快得多。
- 辅助区（预览/状态）做固定矮条、内容区（帧网格）吃 flex 的取舍不变；但任何
  横向工具条要有"窄窗时哪些控件先死"的优先级意识（保存 ≠ 最后一个）。
