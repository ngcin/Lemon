# 2026-09-28 · M6a 批② 热修⑤：选帧对话框底行三钮右溢（替换为整钮出窗）

## 事件

用户截图报：从精灵表添加帧对话框底部「添加 0 帧」「替换为 0 帧」被覆盖——实况
为「添加」右缘贴窗边被裁、「替换为」整钮在窗外不可见；右栏 meta 提示文字右侧
同源裁字。[批文件](../Plans/M6a/2026-09-28-b2-sheetpick-footrow-fit.md)。

根因 = 底行右对齐公式按两钮宽（`bw*2 + spacing`）让位，底行实为三钮（取消/
添加/替换为）整行右溢 ~150px。`git log -S` 考古：公式与替换钮同批出生于 9137fcb
（T3c→T3-UX4 收口）——出生缺陷，非后续回归。

修：按三钮整行宽让位（锚点顺带改精确式消 WindowPadding 残差）+ 同对话框 meta
提示按栏宽换行。同类排查 `SetCursorPosX` 右对齐家族全链（工具栏中段/右段、
Inspector slack）无其他活口。

## 验证

- 回归锁：`sheetpick.replace/win` 矩形探针 + smoke f80 越窗断言（TestHooks
  每帧清空 → 断言落开窗帧）；阴性验证旧公式 `row=NO => FAIL` 红 → 修复复绿
  `row=YES => OK`。
- 回归 full **14/14**（首跑 smoke-drag/ui 负载抖动 12/14，整套复跑全绿——T1/T3
  同款先例）；ctest 3/3。

## 教训

- **右对齐/居中公式与按钮数是强耦合**：给底行加第三个按钮（替换为）时没人重算
  让位宽——公式正确性没有回归位盯着就静默腐烂。工具栏中段公式（按三钮算）当年
  写对了，纯靠手稳。此类布局锁的断言对象 = 最右控件矩形 vs 容器窗矩形（本轮
  落法），加按钮即越窗自动红。
- 用户口中的"被覆盖"未必是遮挡（z 序）：先看截图实况再定方向——本例是整行
  右溢出窗，与覆盖无关。
