# M7c 批⑨ 后修：真人走查两缺陷 + SDK 跨局复位通道 + runtime 暂存陈旧构建 bug

- 日期：2026-10-09（批⑨ 提交 9b87dd5 后同日）
- 关联：[批⑨ 批文件](../Plans/M7c/2026-10-09-b9-svr-test-multiscene.md) · [批⑨ DevLog](./2026-10-09-m7c-b9-svr-test-multiscene.md)
- 性质：批⑨ 真人走查首轮实报两缺陷（火山不刷怪 / 二次 Play 全灭）的修复 + 两个连带挖出的系统性缺口（SDK 用户静态跨局无复位通道；lemon-game runtime 暂存陈旧）。

## 实报两缺陷与根因

1. **火山不刷怪**：`Play 装配：脚本类型未注册（跳过）'VolcanoTableLoader'`——场景脚本经 `Lemon.Behaviours.Register` 才能解析，批⑨ 加了子类漏注册。修 = GameMain 注册（Grass 的 WaveTableLoader 本就在册故草地正常）。
2. **Stop→再 Play 全灭（无菜单无实体）**：`GameFlow.Booted` 种子守卫是**用户静态**——同域跨 Stop/Play 存活（编辑器重进 Play 不换域；`lemon_play_reset` 只清 SDK 内部三表：Events 待发/UI 计数/SceneManager 记忆化 + Behaviours.ClearInstances 清实例表，**用户静态无人清**）→ 新一局的 MainMenu 种子被旧局守卫误判重装副本而自毁 = 全局无流程壳。日志证据 = 后续三次 Play 均无换场/无告警/无实体。

## 修复面

- **SDK 新公共面 `Lemon.Events.PlayResetHook`**（`lemon_play_reset` 时逐订阅广播、异常隔离红字）：用户「每局一份」静态的自清通道——此前无通道（`ClearInstances` 只清 SDK 实例表、Stop 快拆 OnDestroy 不达）。真机首例即批⑨ 守卫。
- **GameFlow/LoadingScreen 订阅自清**（svr-test + 模板生成器内嵌串两侧）：`Booted=false` / `s_driver=default`（DDOL 驱动句柄同 bug 类——旧局句柄跨 World id 复用会误判 Alive → 二次 Play 加载屏死驱；LoadingScreen 静态构造订阅一并清 Pending/HoldingGate/GameProgress）。订阅归静态构造 = 每域一次（与 Configure 期订阅同生命周期语义）。
- **连带挖出：`lemon-game` runtime 暂存陈旧（构建系统 bug）**：原 `POST_BUILD` staging 只随 lemon-game 重链触发——SDK `.cs` 单独重编不重链 = exe 旁 `runtime/` 停留旧程序集（本例真机：新 API `PlayResetHook` 缺方法 → `GameFlow` 静态构造 `TargetInvocationException`；排查一度被「SDK dll 已重编」误导——加载路径是 staging 副本不是构建树）。修 = staging 改 `add_custom_target(lemon-game-runtime ALL ... copy_directory_if_different)` 每构建跑（无变化 = 廉价 no-op），`DEPENDS lemon-game lemon-dotnet-asm` 保产物先就位。
- **诊断面小改进**：`Behaviours.Attach` 构造器异常红字 `ex.Message` → `ex`（全异常链——TargetInvocation 包装的内层才是真因，本例直接受益）。
