## §2 核心方案

### 2.1 工具栏三段式（M4.7a）
左 = W/E/R 工具组 + GridSnap；**中 = Play/Pause/单步**（`SetCursorPosX((avail−组宽)/2)`）；
右 = 预留（Layout 下拉，M5）。Play 键态色（决议 D3）：编辑态灰蓝 → 播放态亮蓝、
Stop 红调（Unity 惯例）；Pause/单步仅播放态可用（现状已有）。

### 2.2 网格 v2（M4.7c；前置 = §2.6 P0 修复）
对标 Unity 2D：**两级网格**（minor 8px 高 zoom 才显 / major 32px 常显）+ **X/Y 主轴
高亮** + **原点标记** + zoom 自适应密度（淡出过密线，替换现 512 行截断上限）+ 间距
入主题 token。overlay 线预算：≤0.3ms @ 1k 线（Profiler 面板现成计量）。
（默认开 = 现状语义不变；用户已确认"当前完全看不到网格"是 §2.6 缺陷而非设计。）

### 2.3 视口交互 v2（M4.7c）——差距最大件
1. **一段式拖拽**：mousedown 命中实体即选中并 arm；位移 >4px 进入拖拽（阈值区分
   点击 vs 拖，消除"点一下就挪走"误触）；点已选实体 = 直接 arm——两段感消失。
2. **Move 手柄轴约束**：X/Y 箭头（Unity 红绿同款语义）独立命中，拖 X 只动 x、
   拖 Y 只动 y；中心块 = 自由拖（现状全实体皆手柄、只有自由拖）。
3. **手柄命中测试体系化**：手柄从纯视觉升级为命中优先级 > 实体本体；Rotate 环
   hover 高亮；Scale 角块 hover 放大。
4. **hover 轮廓**：悬停实体亮边（发现性根基）；光标随手柄变化（ImGui SetMouseCursor）。
5. **Esc 取消拖拽**：恢复 dragTfs_ 快照（快照已有，补取消路径 + Undo 不入栈）。
6. 框选多选：**维持 M5+**（本轮 hover 轮廓为其铺底）。

### 2.4 主题 token 化（M4.7a）
`Tooling/Theme.h/.cpp` 单点定义：背景三层/面板底/选中/主强调/警示三级/文本三级/
圆角/内距/网格色——启动 ApplyTheme 一次 + 各处引用 token，删散落字面量。色板对标
Unity 深色（决议 D2，中性深灰，无品牌化色）。

### 2.5 图标体系（M4.7b）
工具栏 6 键（Play/Pause/Step/Move/Rotate/Scale/GridSnap）、Hierarchy 行前图标
（实体类型：空/精灵/相机/带脚本）、资产类型图标（sprite/prefab/script/generic
形状区分——升级现有程序化调色板色块机制）、Add Component 与右键菜单关键项。
实现（决议 D1）：**自绘 16 枚最小集**——程序化图集加形状页（零新依赖，R4 先例
沿用）；质感不够再评估图标字体。

### 2.6 【P0 前置件】overlay 渲染通道缺陷（网格/选框/Gizmo/实体名标签全部不可见）

**现象**：Scene 视口一片平灰——网格线（GridSnap 默认开）、选中实体的青色选框、
Gizmo 手柄（不透明黄色）、实体名标签**全部没有渲染**。用户实测与无头截图双确认。

**证据链（2026-09-20 诊断，探针已还原不入库）**：

| # | 实验 | 结果 | 结论 |
|---|---|---|---|
| 1 | `--smoke --screenshot` 截图 | 网格/选框/手柄/标签全无；精灵（批 1）正常 | overlay 通道整体缺失，非"太淡" |
| 2 | Render() 埋点计数 | `overlay=68` 包/帧、`batches=3`、`instances=90`（6 精灵+68 overlay+16 文本） | **推入侧与 Bake 侧正常**：包齐、批齐、实例齐 |
| 3 | 网格临时改不透明纯黄 20px 粗线（极限对照） | 截图仍无任何黄线 | 缺陷在**绘制侧**；排除 α70/线宽/配色因素 |
| 4 | 交叉观察：批 1（instanceOffset=0）可见；批 2（offset=6，overlay）与批 3（offset=74，文本）均不可见 | —— | **只有首个批可见**，指向非零 instanceOffset 的绘制路径 |

**静态排查已排除**：包推入（SceneViewPanel::OnGui 每帧执行）、overlay 合包
（RenderViewport 追加进 `all`）、Bake 分段（连续同键分段正常）、批键/管线选择
（overlay 与精灵同 atlas/blend/filter，仅 layer 63 不同）、MakeBatchKey/Record 循环、
环形缓冲容量（90 ≪ 4096）、白底纹 spriteId（1，有效）。

**假设排序（下一步按序取证）**：

1. **非零 instanceOffset 的实例寻址断裂**（最高嫌疑）：`pc.baseInstance = segBase +
   batch.instanceOffset` 与 `DrawQuadInstances(count, 0)` 第二参（firstInstance?）的
   语义在 RHI/shader 两侧不闭环——shader 的实例索引用 `gl_InstanceIndex`（含
   firstInstance）还是显式加 `baseInstance`，可能双加/都不加/管道布局未消费该
   push constant。M4.2 验收时 Gizmo/网格可见（截图存档），此后某次优化（环形
   SSBO/baseInstance 引入？）引入回归——需 git 考古定位窗口。
2. 同 pass 内第二次 `BindPipeline` 后动态状态/描述符失效（storage buffer 或
   push constant layout 未随批重绑）。
3. atlas 纹理槽/采样器绑定对 overlay 批的 key 编码有歧义（低嫌疑：与精灵同槽）。

**诊断计划（授权后执行；每步独立提交探针可回退）**：① 读 RHI `DrawQuadInstances`
实现与 sprite shader 实例索引语义，对照 baseInstance 消费链；② git 考古 M4.2 验收
截图之后的 SpriteBatcher/RHI 变更窗口；③ 最小复现：单批 overlay-only 场景
（关精灵渲染）验证非零 offset 是否全灭；④ 修复后 `--screenshot` 基线图入库
（网格/选框/手柄/标签四要素可见性入冒烟断言——此缺陷能穿透 9 项自动化正说明
"渲染结果可见性"无自动防线）。

**影响面**：M4.7c 全部（网格/拖拽手柄/hover 轮廓）+ 手测指南 C5/C6（父子拖拽
视觉反馈）、E2/E3/E5（Gizmo 三态/吸附/F 聚焦的可见反馈）——P0 不修复，视口交互
验证均无从谈起。GameView 无 overlay（withOverlay=false）不受影响，Play 链冒烟
因此全绿——即"自动化 9/9 PASS 与此缺陷并存"的原因。

## §4 风险与砍单序

- **ImGui 视觉上限**：接受"ImGui 风格的 Unity 感"，不追像素级复刻（动画/模糊/圆角
  细节有限）。
- **label-scrub 无 ImGui 原生支持**（Unity 是拖 label 改值）：需自绘交互区——**砍单
  候补首位**。
- 图标字体引入破 R4 先例（M4.6 零新库）：走登记流程，或降级自绘。
- 网格 LOD 与手柄命中的增量帧成本：Profiler GPU/CPU 列验收，超标即降级。

砍单序：label-scrub → 图标字体降自绘 → hover 轮廓 → GameView Aspect → Layout 下拉。
