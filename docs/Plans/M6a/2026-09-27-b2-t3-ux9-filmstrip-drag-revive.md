# T3-UX9 胶片带三修：列宽公式 / 拖拽通道复活（交互帧格）/ 提示文案

2026-09-27 · 批② 动画生产线 · 用户截图报点三问题讨论后方案 A 定案实施。

## 背景（用户三报 + 对账结论）

1. **宽度**：帧列表右侧空约一格半但帧换行。根因 = 列数公式按
   `stripEdge + 2×FramePadding + 间距` 算每格占宽，而帧格实际只是裸图片
   （无填充）——每格虚耗 8~16px（高分屏更大）→ 列数低估 → 提前换行。
2. **拖拽重排无效 / 拖图入格没法拖**：根因 = 帧格用裸 `ImGui::Image`（**无
   ID**）——查 ImGui 源码：无 ID 项做拖源必须带 `SourceAllowNullID` 标志
   （代码没带 → 每帧 return false），拖靶/右键只认图矩形。**三通道自出生即
   死**（冒烟从未覆盖 + 真人未试过 = 一直没暴露）。
3. **"左右箭头多选"误会**：←/→ 是移选（光标）不是多选——旧提示文案歧义；
   Ctrl/Shift+点击多选已存在且好用。

## 决策（用户拍板：方案 A——修而非砍）

修宽度 + 帧格改交互件救活全部拖拽 + 文案改准（用户原话取向："要换就删了
重加，功能加太多是干扰"——但拖拽重排对调帧序价值高，选择修复）。

## 改动

- **列宽**（`DrawFilmstrip`）：`step = stripEdge_ + ItemSpacing.x`（对齐真实
  推进），帧排满整行不再虚耗。
- **交互帧格**（`DrawCellImage` 加 `idStr` 参数）：非空 = `InvisibleButton` +
  drawlist `AddImage` 直贴（占位格 = 矩形 + 居中字形，同走 drawlist）；胶片带
  格传 `"##cell"`（PushID(i) 内唯一）、预览图传 `"##pvimg"`（拖入加帧目标挂
  真交互件）；模态行图等纯展示路径不变。浏览器瓦片（ImageButton）本就是该
  模式——拖源侧本来就健康，问题全在目标侧。
- **文案**：`帧列表（单击选中 · Ctrl/Shift+点击多选 · ←/→ 移动选择 · 拖拽重排
  · 拖图入格换图/入尾加帧 · Del 删 · Ctrl+D 复制）`。
- **冒烟回归锁（语义断言）**：`StripCellItemForTest()`（渲染侧缓存本帧帧格
  ImGui 项 ID）——非零 = 真交互件；0 = 退化成裸 Image = 拖拽通道死。f118
  断言 + RESULT `drag(item=)` 位。**阴性验证过**：sed 回裸 Image →
  `drag(item=NO)` FAIL → sed 恢复复绿。
- 回归脚本 anim 步保持 `--frames 120`（语义断言不占帧预算）。

## 排障记录：为何不注入真拖（重要，后续会话会再撞）

尝试过四轮注入时序（按下即移 / 按下保持一帧再移 / 先悬停一帧再按下 / 链帧
关 M4.5 扫掠）全部失败，取证链：

- 注入坐标/按键全落位（按下帧 `clicked=1`、cell 悬停 `HoveredId==cellId`、
  位移超拖活阈值）——但 `ActiveId` 始终不是帧格，一帧后变成 strip 子窗口的
  兜底 id（窗口 MoveId 一类）。
- 根因 = **注入点击在普通（非模态）窗口会被 ImGui 1.91 的窗口兜底路由吃掉**：
  悬停是注入帧内瞬移建立的，点击路由时序上撞上"HoveredId 为空 → 点击绑
  窗口"路径。**既有注入点击链（animset.create / picker.tile / clipcreate.ok /
  picker.cancel）全部在模态窗里，路由不同，所以从未暴露**。
- 真人鼠标有连续真实事件流（先悬停再按下、微抖非瞬移），不受影响。
- 结论：拖拽手感/重排/入格换图归**真人验收**；冒烟用项 ID 语义锁锁住
  "帧格必须是交互件"这一回归类（正是本次事故的根因特征）。
