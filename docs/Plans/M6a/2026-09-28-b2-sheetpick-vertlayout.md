# 选帧对话框上下结构（参数上移横条 + 图区吃满全宽）

2026-09-28 · 批② 动画生产线 · 用户建议（"很多 sprite sheets 会很长，左右结构
会挤压横向宽度"），同日继底行三钮右溢热修⑤之后的第二件。

## 背景与决策

v3.1 布局 = 左图区（吃余宽）+ 右参数栏（固定 252px）。长条精灵表（横排循环、
多方向条）横向像素是硬需求，780 宽窗口被右栏吃掉 252 后图区仅 ~510px。用户
定案改上下结构，评估同意：

1. **参数上移为顶部两行横条**（分割 / 选择+模式+视图 横排；`paramH` 按两行
   控件高公式化，非魔数）。三组控件全是短控件，横排两行 ~78px 足够。
2. **图区吃满全宽**（`ImVec2(0, -footH)`）：zoom=1 初始 fit 从 ~510px 升到
   ~756px，宽幅可视面积 +48%；fit 上限 640/440 是侧栏时代定的，一并解放
   （`max(avail,160/120)` 地板保留防 0）。
3. **窗口 560 → 600**：参数条吃掉的纵向高度还一部分回来，方形/偏高表不吃亏。
4. **meta 提示移底行左空档**：右栏时代它按栏宽换行防裁（热修⑤顺手件），
   横条时代行宽吃紧 → 移到底行左侧（右对齐三钮天然留出的空档，SameLine 防
   顶出第二行——底行高 = -footH 预留死）；cell 信息文字补同文 tooltip。
5. **计数读 `pickCountLast_`**（上帧缓存）：参数条先于图区渲染，`cnt` 本帧
   在图区子窗末更新（探针同值）——文本滞后一帧无感；两开窗路径（真实流 +
   OpenSheetPickForTest）补 `pickCountLast_ = 0` 归零，防吃上一次会话残值。
   冒烟断言读探针在点击后 ≥3 帧，不受文本滞后影响。
