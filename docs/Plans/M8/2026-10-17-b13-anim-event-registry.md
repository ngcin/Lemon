## 1. 输入与定形（用户 2026-10-17 拍板）

- **动因**：批⑫ 打点链路落地后，作者面残余负担聚焦两点——**魔法数字 id**
  （clip 写 1、脚本订 2 = 全场静默无事发生）与**发现性**（编辑器看不到 id 含义
  与消费者，反向引用靠 grep）。对游戏开发者是持续负担（按 id 个数线性涨）。
- **病与药的同构先例**：ADR-013 当年治 GUID 魔法常量（`Anim.ClipId
  ("5bd31a7c…")` 手抄进脚本）= 把隐式约定物化为数据 + 按名解析。帧事件 id 是
  同一病程的下一站，药方同构：**项目级事件注册表**。
- **三面目标**（架构评审定形）：作者见名字下拉；C# 见**启动期红字校验**（拼错
  名字 = 启动第 0 帧报错，不再静默）；运行时仍 `u16 id` 逐位比较——名字装载期
  解析完，热路径零反射零字符串（**金回放零重录前提**）。
- **触发条件放宽**：原登记"第二个项目复用打点协议出现即做"→ 用户直接立项
  （svr-test 已有两个手写打点资产 + DuelBehaviour 真实消费者，负担起点已到）。

### Out（明确不做，含否决理由）

- **Unity 式方法名绑定**（反射 + 每预制体各自绑）：改名静默断、换皮分叉、热路径
  反射——三输；
- **Unreal Anim Notify 式类注册**：发现性最佳但每事件一个类锅炉 + 反射耦合，
  注册表 + 下拉拿八成体验；
- 代码生成 / 引用图 UI（lint 三件先行，第二项目再议）；字符串 payload（v1.1）；
- **id 线上格式不变**：数字协议是运行时与 .clip 档面的既有格式，本批不迁移
  不重录（Monster01/02 裸 id 档照常开/存/播）。

## 3. 设计要点

- **确定性论证**：名字不入模拟态——装载期解析为 id 后，模拟/回放/哈希流只见
  u16（ADR-013 参数名同款论证）；注册表缺表/坏行 = ADR-012 缺表保底哲学
  （裸 id 模式照常工作，编辑器降级显 `#N（未命名）`）。
- **id 分配稳定性**：注册表行删除后 id 不回收复用（防旧 clip 打点语义漂移）；
  「新建事件」分配 = 当前最大 id + 1；手写表允许跳号不允许改既有行 id
  （编辑器检测到 id 变更 → 红字提示新建行替代）。
- **与批⑫ 衔接**：CommitEvent 校验面从"id ≤ 65535"扩为"名字已注册"（裸 id
  仍可存——兼容旧档编辑），TrySave roundtrip 等值面不变；未注册 id 的 lint
  与"未命名 badge"只告警不拦（warn-once 哲学）。
- **订阅期红字的实现面**：`Anim.OnFrame` 解析失败走 Console 红字 + 该订阅
  挂空（不影响其他订阅）；Define/表 双源冲突（同 id 异名/同名异 id）= 启动
  红字，以表为准。

## 4. 分期（三段各自独立出口，可停在任何一步）

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 注册表缺表/坏行打断装载 | ADR-012 缺表保底：裸 id 模式照常，编辑器降级显示 |
| id 手改导致旧 clip 语义漂移 | 分配后永不变更 + 编辑器检测 id 变更红字 |
| Anim.OnFrame 糖破坏 C++/C# 边界纪律 | 仍是事件队列上的订阅糖（vtable 零新增）；解析一次发生在装载期 |
| payload 进哈希流致回放漂移 | payload 值经 EventPacket 既有字段入流（批⑫ 前论证同款）；单测钉 |
