# docs — 文档地图与规约

一页纸说清：什么内容写到哪里、怎么命名、生命周期如何流转。**不设任何 INDEX/总目录文件——目录树本身即索引**（文件名带日期，排序即时间线）。

## 目录地图（五区制）

| 目录 | 定位 | 更新方式 |
|---|---|---|
| `EngineDesign/` | **长期设计基准**（活文档）：00 总纲 → 01 架构 → 02 渲染 / 03 ECS / 04 C# / 05 编辑器 / 06 资产 / 07 移植矩阵 / 08 路线图 / 09 测试 + `Editor-Manual-Test-Guide.md` + `Windows-Build-Guide.md` | 原地修订；动工前必读对应分册 |
| `Plans/<里程碑>/` | **计划与批次分解**：每批一个文件；`<M>.md` 为该里程碑唯一枢纽页（批次表 + 链接 + 收口状态） | 开批新建文件，完工文内勾销 |
| `DevLog/` | **事后事件流水**：开发日志（bench 数字 / 事故 / 手测轮 / P0 发现），一条目一文件 | 只增不改；写完即终稿 |
| `ADR/` | **推翻既定设计的决策记录**，`ADR-NNN` 延续编号 | 只增不改 |
| `Reports/` | **一次性快照**：评审 / 测试报告 / 走查 / 复核清单 | 产出后不更新 |
| `Baselines/` | 基线截图等静态资产 | — |
| `Archive/` | **冻结历史**（如 Prowl2D 路线）：不再编辑、不作现行依据、其内部断链豁免修复 | 迁入时加归档注记，此后冻结 |

## 命名规则

- `DevLog/` 与 `Reports/`：`YYYY-MM-DD-<英文slug>.md`，日期 = 事件发生日（报告以出具日为准）。
- `Plans/` 批次文件：`YYYY-MM-DD-<批号>-<slug>.md`，日期 = 批次开工日；里程碑总览固定名 `<M>.md`。
- **章节编号跨文件沿用全局编号**：M5 各批文件共享原总计划编号 §1–§25，因此「`M5.md §16.2`」式引用一律可在 `Plans/M5/` 目录内直接 grep 定位，无需知道所在文件。

## 文体分流（写什么 → 去哪）

| 内容 | 去处 |
|---|---|
| 事件、实测数字、事故复盘、手测轮、P0 发现 | `DevLog/` 新条目 |
| 开工前的批次现状盘点、设计决策、任务分解、验收判据 | `Plans/<里程碑>/` 新批次文件 + 总览页登记一行 |
| 设计基准的修订（语义 / 接口 / 约定变化） | `EngineDesign/` 对应分册原地修订；推翻既定设计另写 `ADR/` |
| 评审、测试报告、走查、复核 | `Reports/` 一次性快照 |
| 里程碑出口判据与阶段登记 | `EngineDesign/08-Development-Roadmap.md` |

## 生命周期

- **Plans** 文件头第二行：`Status: planned` → `in-progress` → `done（日期）`；完工判据在文内勾销，事件与实测数字记 `DevLog/` 同日条目。
- **DevLog** 条目写完即终稿，不回改；勘误以「追记」小节追加。
- **Archive** 永久冻结：不编辑、不翻译、不重排版；活跃文档可链接它作历史参照，但它不是现行依据。
- **引用规范**：跨文档一律相对 markdown 链接（可机械检查、移动不失效）；提及章节用「`<文件名> §N`」记法。

## 维护纪律

- 新事件 = 新 DevLog 条目文件；**不**把内容追加进旧条目或其他文档末尾。
- 新批次 = 新 Plans 批次文件；**不**在里程碑总览页滚动追加批次正文（总览页只放表格与链接）。
- 单文件超过 ~30KB 即是拆分信号：按上述文体分流，而不是继续追加。
- 单 `.cpp` 超过 ~2,000 行即是拆 TU 信号（M7c 批⓪ 起；引擎 27.6k 行现最大 RHI.cpp 1,727 达标；超线随消费者批次拆，不做专项）。
- 迁移/拆分只动文件组织与引用指针，不改写史实内容。
